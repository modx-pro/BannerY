# FAQ BannerPro

## Баннеры не выводятся на сайте

1. **pdoTools не установлен** — сниппет вернёт `You need to install pdoTools to use this snippet!`
2. **Неверная позиция** — используйте `positionName=sidebar` или `position` с **ID** позиции из админки/БД
3. **Баннер неактивен** или вне диапазона дат `start` / `end`
4. **Нет связи баннера с позицией** — проверьте вкладку позиций в админке
5. **Кэш** — очистите кэш MODX и браузера
6. **Контекст позиции** (с 4.5.0) — если у позиции задан `context_key`, баннеры видны только в этом контексте MODX; пустое поле = все контексты

Проверка с логом (под менеджером):

```fenom
{'!BannerPro' | snippet : ['position' => 3, 'tpl' => 'byAd', 'showLog' => true]}
```

## Картинки не отображаются

1. Проверьте **bannerpro_media_source** и источник у конкретного баннера
2. Путь к файлу в media source должен быть корректным
3. У баннера поле `image` заполнено в админке

## Клики не считаются

1. Плагин **BannerProClickout** включён на **OnPageNotFound**
2. Ссылка в чанке ведёт на `{$click_url}` (clickout), не на прямой URL баннера
3. `adposition` — ID из `bannerpro_ads_positions`, не `id` баннера
4. Повторный клик с того же IP в тот же день не увеличит счётчик (по дизайну)
5. Friendly URL не должен перехватывать путь раньше MODX (проверьте `.htaccess` / роутинг)
6. **Фильтр ботов** (с 4.6.0): при `bannerpro_filter_bots = Да` клики с User-Agent ботов (Googlebot и т.д.) не записываются — нужен пакет CrawlerDetect; без него фильтр не работает

## Статистика занижена / нет кликов от ботов

С 4.6.0 настройка **Фильтр ботов** (`bannerpro_filter_bots`) исключает из статистики запросы, определённые как боты. Установите дополнение [CrawlerDetect](https://modstore.pro/packages/other/crawlerdetect) и включите настройку. Исторические данные не пересчитываются.

## Баннер активен, но не виден на сайте

1. Проверьте **start** / **end** (календарный период)
2. **Расписание показа** (4.6.0): поле `show_hours` — дни недели и часы; вне слота баннер скрыт
3. **Таргетинг** (4.6.0): `target_resource_id` / `target_parent_id` — баннер только на нужных страницах
4. **Метки** (4.6.0): при `&tags=` в сниппете баннер без меток не попадёт в выборку
5. Лимиты `max_clicks` / `max_impressions` — баннер скрыт при достижении порога

## Админка не открывается / пустая страница

1. Установите **VueTools**
2. Выполните `npm run build` перед сборкой транспорта
3. Проверьте консоль браузера и наличие `bannerpro-admin.min.js` в assets
4. Нужно право **view** в менеджере

## Fenom-чанк не рендерится

1. В pdoTools включена поддержка Fenom для чанков
2. Используйте `@FILE path/to/template.tpl` в параметре `tpl`
3. При проблемах с вложенными тегами попробуйте `fastMode => true`

## Как вывести баннеры по имени позиции, а не по ID?

Используйте параметр **`positionName`** (с 3.2.0) или синоним **`positionKey`**:

```fenom
{'!BannerPro' | snippet : ['positionName' => 'sidebar', 'tpl' => 'byAd']}
```

Если заданы и `position`, и `positionName`, приоритет у `position`. Кастомный `innerJoin` к `byPosition` — только для продвинутых сценариев, см. [frontend-guide.md](frontend-guide.md).

## Можно ли вставить произвольный HTML вместо изображения?

Да. С 3.2.0 в админке выберите тип **HTML** и вставьте код (AdSense, embed и т.д.). Сниппет выведет его через чанк **`byHtml`** (или `tplHtml` / `tplHtml*`).

При заданном `url` HTML оборачивается в ссылку клика через `{$click_url}`. Без `url` выводится сырой HTML (только из доверенной админки).

Пример:

```fenom
{'!BannerPro' | snippet : [
  'positionName' => 'sidebar',
  'tplHtml' => 'byHtml'
]}
```

## Баннеры MiniShop3 не показываются на карточке товара

1. Передайте **`productId`** в сниппете — ID текущего ресурса (`{$_modx->resource.id}`)
2. В админке у баннера либо **пустой** `product_id` (глобальный), либо **тот же** ID товара
3. На каталоге и главной `productId` **не указывайте** — иначе отфильтруются только глобальные баннеры
4. [integrations/minishop3.md](integrations/minishop3.md)

## Плейсхолдеры product_* пустые

1. У баннера в админке задан **товар** (`product_id > 0`)
2. У товара заполнены TV `price`, `old_price`, `thumb` (или `image`)
3. Товар существует и опубликован (`msProduct`)

## Админка на английском / украинском, а подписи смешанные

1. Проверьте **manager_language** в настройках MODX
2. Пересоберите бандл после обновления: `npm run build`
3. Ключи UI передаются из PHP (`bannerpro_build_mgr_lexicon`); в JS не должно быть захардкоженных русских строк

## Как подключить GA4 / Matomo / Яндекс Метрику?

1. Включите плагин **BannerProAnalytics** и настройку `bannerpro_analytics_enabled`.
2. Счётчики GA4 (dataLayer), Matomo (`_paq`) или Метрики (`ym`) должны быть уже на странице.
3. Для своей логики подпишите плагин на `OnBannerProClick` / `OnBannerProImpression` на сервере.

Подробно: [integrations/analytics.md](integrations/analytics.md).

## На демо-странице «плагин не установлен» / analytics.js не загружен

1. **Продакшен:** **Элементы → Плагины** → включить **BannerProAnalytics**; `bannerpro_analytics_enabled` = Да; `php clear_cache.php`.
2. **Стенд `bannerpro-test.html`:** запустите `php core/elements/demo/seed_bannerpro_demo.php`. Секция 19 подключает `analytics.js` фолбэком, даже если плагин выключен.
3. Если в таблице статуса всё «красное», а в MODX настройки верные — проверьте шаблон `bannerpro_test.tpl`: при Fenom `{extends}` переменные `{set}` должны быть **внутри** `{block}`, не между блоками. Очистите кэш Fenom: удалите `core/cache/pdotools/file`.

См. раздел «QA без реальных счётчиков» в [integrations/analytics.md](integrations/analytics.md).

## Пикер товара MS3 не находит товар / мало позиций в списке

1. MiniShop3 установлен, товары — `msProduct`, опубликованы.
2. Введите часть названия в фильтр MultiSelect — список строится сервером (до 200 совпадений).
3. Без ввода показываются первые 200 по алфавиту, не весь каталог.
4. Привязанный при редактировании товар всегда виден в списке.

Подробно: [integrations/minishop3.md](integrations/minishop3.md#админка).

## Показы не считаются / CTR нулевой

1. `bannerpro_track_impressions` = Да
2. Плагин **BannerProImpression** на `OnPageNotFound`
3. На фронте есть `impression.js` (подключается сниппетом при включённом учёте)
4. Баннер попадает в viewport (Intersection Observer)

## Webhook на клик не срабатывает (4.5.0)

1. **`bannerpro_webhook_url`** задан и начинается с `http://` или `https://`
2. URL не указывает на `localhost`, `127.0.0.1` или private IP — такие адреса блокируются
3. Проверьте лог MODX (`core/cache/logs/`) на `[bannerpro] Webhook failed`
4. Редирект после клика не ждёт успешного ответа webhook; timeout запроса — 2 с

Подробнее: [configuration.md](configuration.md#webhook-при-клике-с-450).

## Статистика «Сегодня» показывает старые даты (исправлено в 4.5.0)

Если в фильтре выбрано **Сегодня**, а на графике и в сводке видны данные за прошлые дни (например 07–08.06 при текущей дате 26.06) — это был баг фильтра периода: запрос фактически шёл как «за всё время». Обновите пакет до **4.5.0-pl** или новее.

После обновления при «Сегодня» без событий за текущий день: сводка **0 / 0**, график — одна точка с сегодняшней датой и нулями.

## Где взять ключ REST API?

1. **Система → Настройки системы** → `bannerpro` → **`bannerpro_api_key`** (подпись «REST API ключ»).
2. Включите **`bannerpro_api_enabled`** = Да.
3. В `curl` замените `YOUR_API_KEY` на значение из настройки: `-H "Authorization: Bearer <ключ>"`.

Ключ не связан с логином менеджера. При пустом поле — переустановите/обновите пакет или задайте свой токен вручную. Подробнее: [rest-api.md](rest-api.md#ключ-api).
